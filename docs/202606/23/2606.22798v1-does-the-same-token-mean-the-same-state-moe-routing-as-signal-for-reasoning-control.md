## 摘要
在稀疏混合专家语言模型中，相同的词元ID是否意味着相同的路由器状态和产生它的相同专家？在重复锚点处固定发射的词元ID后，我们发现并非如此：产生它的专家仍然分离任务上下文、轨迹历史和推理努力模式。这种残差结构支持测试时控制：在接近边界锚点（最终响应转换）和分隔符锚点（打开答案，例如 \texttt{\textbackslash boxed\{} 或代码围栏）处，路由邻域已经在标记只读时与最终答案盆地对齐，并且在答案打开时读取路由时最强。我们将其操作化为RAD（路由一致性解码），一种免答案字符串的多展开选择器：它定位固定锚点，通过锚点窗口的MoE路由状态表示每个展开，并返回最密集的加权Jaccard K近邻路由盆地中心，无需解析、归一化、执行或对答案字符串进行投票。在10种稀疏MoE配置（gpt-oss、Qwen3-MoE）和涵盖数学、GPQA和代码的6个数据集上，RAD在字符串投票适当时与多数投票相当，具有小的正配对差异（RAD 73.9 / RAD+DC 74.2 vs. 多数投票 73.6）。与多数投票类似，RAD不是验证器：密集的错误盆地仍可能获胜。其价值在于接口：相同的选择器在精确字符串投票不适用的代码上直接给出pass@1，并且相同的路由密度原则，重新锚定到代理边界，在SWE-bench Verified上比随机选择改进了最佳16的补丁选择，其中补丁没有可供投票的答案字符串。

## Abstract
In sparse Mixture-of-Experts language models, does the same token id imply the same router state and the same experts producing it? Holding the emitted token id fixed at repeated anchors, we find it does not: the experts that produce it still separate task context, trajectory history, and reasoning-effort mode. This residual structure supports test-time control: near \emph{boundary} anchors (the final-response transition) and \emph{delimiter} anchors (which open the answer, e.g.\ \texttt{\textbackslash boxed\{} or code fences), routing neighborhoods already align with final-answer basins at a marker-only readout and strongest when the routing is read at the answer opening. We operationalize this as \textbf{RAD} (Routing Agreement Decoding), an answer-string-free multi-rollout selector: it locates a fixed anchor, represents each rollout by its anchor-window MoE routing states, and returns the densest Weighted-Jaccard $K$-NN route-basin center, without parsing, normalizing, executing, or voting over answer strings. Across 10 sparse-MoE configurations (gpt-oss, Qwen3-MoE) and 6 datasets spanning math, GPQA, and code, RAD is on par with Majority where string voting is well-posed, with small positive paired deltas (RAD $73.9$ / RAD+DC $74.2$ vs.\ Majority $73.6$). Like majority voting, RAD is not a verifier: a dense \emph{wrong} basin can still win. Its value is the interface: the same selector gives direct pass@1 on code, where exact-string voting is ill-defined, and the same routing-density principle, re-anchored to the agentic boundary, improves best-of-16 patch selection on SWE-bench Verified over random, where patches have no answer string to vote on.

- **隐含含义**：传统的多展开聚合方法（如多数投票）依赖于最终答案字符串的解析和规范化，在代码生成或复杂代理任务中变得脆弱甚至不可行。论文提出**路由状态本身就可以作为路径选择的无答案信号**，从而提供更灵活、更通用的测试时控制接口。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：利用MoE路由器在**固定锚点**（如答案分隔符 `\boxed{`、代码围栏或最终响应边界标记）处的路由状态，衡量多条展开路径之间的**路由一致性**，并选择处于最稠密路由“盆地”中的展开，以此作为最优结果，无需读取、解析或投票最终答案字符串。
- **关键技术细节**：
  - **锚点定位**：根据任务类型选择锚点。数学/GPQA用 `\boxed{`，代码用三个反引号围栏，代理任务用思考→行动转换标记（如 `</think>` 或 `<|start|>`）。
  - **路由表示**：对于每条展开，在其锚点处取长度为 \( W \)（默认16）的词元窗口，收集每个词元对应的路由向量（每个MoE层选中的专家ID及其softmax权重），逐层拼接后求平均，得到一个稀疏的加权专家直方图 \( z_i \)。
  - **相似度度量**：使用**加权Jaccard**（Weighted Jaccard）计算两展开路由向量的相似度：
    \[
    \text{WJ}(u,v)=\frac{\sum_e \min(u_e,v_e)}{\sum_e \max(u_e,v_e)}
    \]
    该度量保留了路由权重的连续信息，而非仅二值化专家激活。
  - **选择规则**：计算每条展开的 \( K \)-近邻（K=10）密度 \( q_i = \sum_{j\in\text{KNN}(i)} S_{ij} \)，选择密度最高的展开 \( i^* = \arg\max q_i \)。
  - **免答案字符串访问**：RAD只使用词元ID定位锚点，以及锚窗内的路由张量；从不读取、解析、比较、执行或投票任何最终答案内容。
  - **融合方案（RAD+DC）**：先用DeepConf的置信度标量过滤出置信度最高的半数展开，再在此子集上计算RAD密度，以此结合共识信号与置信度信号。

## 6. 主要结论与发现

1. **相同词元不表示相同路由状态**：锚定词元时，路由状态仍然分离任务、问题和推理努力模式，KNN交叉污染率低于5%。
2. **路由邻域与答案盆地对齐**：在分隔符锚点的16词元窗口处，路由$K$-NN纯度（$A_{\text{Knn}}$）达到最高，且在多个模型上该纯度与选择器准确率高度相关（Spearman ρ≈0.72–1.0）。
3. **RAD性能**：
   - 在字符串投票适当时（数学+GPQA），RAD（73.9%）和RAD+DC（74.2%）与多数投票（73.6%）持平，小正差异不显著（RAD+DC 比多数投票高0.57pp，95% CI [-0.22, +1.35]）。
   - 在代码生成任务上，RAD直接输出pass@1选择，显著高于随机基线（RAD 67.1% vs Avg@64 66.5%），而多数投票因输出唯一性无法应用。
   - 在SWE-bench Verified代理场景上，RAD在可判定子集上提升+4.7–5.0pp，整体提升+2.2–2.9pp，均优于随机。
4. **RAD是共识信号而非验证器**：当正确展开占多数时RAD有效，当错误展开占多数时RAD也会选择错误（与多数投票类似）。与DeepConf置信度标量正交融合后（RAD+DC）在低正确率区域获得互补增益。
5. **路由信号鲁棒**：二值化Jaccard与加权Jaccard无统计差异；最浅层十分之一路由即可达到接近全网络的选后准确率，降低了捕获与存储成本。

## 7. 优点：方法与实验设计亮点

- **答案字符串无关接口**：核心贡献。RAD不依赖最终答案的提取、规范化或投票，因此天然适用于代码生成（输出唯一性强）和代理任务（输出无短答案字符串）等多数投票难以处理的场景。
- **轻量高效**：路由捕获仅增加约7%生成开销，选择步骤在CPU上实时完成，且只需保存锚点窗口的路由数据，存储成本低。
- **强可解释性**：$K$-NN密度与答案盆地纯度的对应关系得到定量分析，且层深度消融表明信号在浅层已足够，有利于解释模型内部何时达成“共识”。
- **统计严谨性**：实验报告了配对置信区间、McNemar精确检验、多假设校正（Holm、BH-FDR）、功效分析（核函数比较）。消融控制清晰，结论可靠。
- **跨模型泛化性**：方法在三种不同MoE设计（小专家池、中专家池、超大专家池+共享专家）和10种配置上表现一致，无需调整参数。

## 8. 不足与局限

- **需要MoE路由访问**：RAD要求模型每词的top-K专家ID和权重，这对于密集模型或无法提供路由信息的封闭API不可用。
- **仅适用于路径后选择**：RAD作用于已完成的展开池，无法打断生成或提前停止，相对于在线剪枝方法（如前缀一致性、置信度早停）在延迟上无优势。
- **非验证器性质**：在错误多数场景下RAD表现不佳，且数学/科学池中与多数投票的差距极小且不显著（RAD-Maj +0.28pp, p=0.52），主要价值在于扩展了可处理的任务类型，而非提升准确率。
- **代码/代理场景提升温和**：在代码任务上仅比随机高约0.6–0.8pp（RAD 67.1% vs Avg@64 66.5%）；在SWE-bench上的端到端提升2–3pp，离oracle（69.8–75.8%）尚有较大差距。
- **锚点依赖**：方法依赖于固定锚点的可靠出现。虽然论文给出了锚点覆盖率和备用方案，但在某些极端截断或无锚点展开中可能造成选择偏置。
- **实验完整性**：未探索温度、top-p等超参数对路由信号的影响；未与最近期的基于内部神经元的选后方法（如NEX、DeepConf加权投票）在同条件公平比较；代理场景仅使用单一agent框架，未见跨框架鲁棒性验证。

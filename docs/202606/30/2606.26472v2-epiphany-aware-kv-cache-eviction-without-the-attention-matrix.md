## 摘要
随着推理模型生成长达数万token的思维链，KV缓存日益成为部署瓶颈。现有缓存淘汰方法通过注意力权重对token进行排序，但在长推理轨迹中该重要性代理指标存在噪声，且强制模型实例化注意力矩阵会阻碍生产推理中融合内核的使用。本文提出一种基于新指标——“顿悟分数”的token评分方法：该指标直接从前向传播中读取模型内部表征的变化，无需注意力矩阵且额外状态开销可忽略。由此产生的缓存淘汰方法EpiKV无需训练、分类器或定制内核，可直接在不改变FlashAttention推理栈的情况下使用——相较于基于注意力的评分方法，其可行上下文长度扩展16倍。我们通过分析层间顿悟分数分布（发现上层中间层为负向），并采用因果滚动z分数消除位置趋势。在4096 token缓存下，EpiKV在MATH-500上达到72%，与最强注意力基线（ThinKV 71%，H2O 67%）持平；滞后归一化KV变体在8192 token下AIME-2024上达到37%（最优基线为33%），速度提升达2.8倍。

## Abstract
As reasoning models emit chains of thought tens of thousands of tokens long, KV cache increasingly becomes a deployment bottleneck. Existing cache eviction methods rank tokens by attention weight, which is a noisy importance proxy in long reasoning traces, and prohibits the use of fused kernels in production inference by forcing the model to materialize the attention matrix. In this work, we instead score tokens with a metric we term the epiphany score: the change in the model's internal representation, read directly from the forward pass with no attention matrix and negligible extra state. Our resulting cache eviction method, EpiKV, requires no training, classifier, or custom kernel, and can be used directly in FlashAttention inference stacks unchanged -- scaling to a 16x longer feasible context than attention-based scoring. upper-mid layers negatively) and remove a positional trend with a causal rolling z-score. At a 4096-token cache EpiKV reaches 72% on MATH-500, matching the strongest attention-based baseline (ThinKV 71%, H2O 67%); a lag-normalized KV variant reaches 37% on AIME-2024 at 8192 tokens against the best of them (33%), at up to 2.8x the speed.

## 1. 核心问题与整体含义

- **研究动机**：推理模型（如 DeepSeek-R1）生成的思维链动辄数万 token，导致 KV 缓存线性增长，成为部署中的内存与速度瓶颈。现有解码时缓存淘汰方法普遍依赖**注意力权重**来排序 token，但注意力权重在长推理轨迹中是噪声很大的重要性代理（例如注意力汇吸引大量权重、填充词获得高权重却无实际贡献），且必须物化完整的 n×n 注意力矩阵，这迫使模型使用 eager 内核，无法利用 FlashAttention 等融合内核，导致 GPU 内存耗尽（80 GB A100 在 8192 token 时已 OOM）。
- **整体含义**：提出一种**无需注意力矩阵**的缓存淘汰方法，仅从模型标准前向传播中读取隐藏状态变化，即可在保持相当准确率的同时，实现 16 倍于注意力评分的可行上下文长度，显著提升生产部署效率。

## 2. 方法论

- **核心思想**：使用**顿悟分数 (epiphany score)** 衡量 token 重要性——即生成该 token 时模型隐藏状态的变化幅度。大的变化标志着“顿悟”token（如中间结论、已完成的步骤、从探索到收敛的转折点），这些 token 最值得保留。
- **关键技术细节**：
  1. **隐藏状态差分**：对层 l 和位置 t，计算 L2 diff：`g_l(t) = ||h_l(t) - h_l(t-1)||_2`。
  2. **两层带解剖**：对 DeepSeek-R1-Distill-LLaMA-8B（32 层），通过反事实遮挡实验发现：**Band A（第 7–13 层）** 与重要性正相关，**Band B（第 18–25 层）** 与重要性负相关。因此构建原始分数 `s(t) = ḡ_10(t) - ḡ_21(t)`（使用因果滑动窗口均值，w=64）。
  3. **位置趋势校正**：原始分数在长序列中随位置单调漂移，因此采用**因果滚动 z-score**：`z_l(t) = (g_l(t) - μ_l(t)) / (σ_l(t)+ε)`，最终评分 `s(t) = z_10(t) - z_21(t)`，此即为 **EpiKV** 的主要方法。
  4. **KV 向量变体**：除隐藏状态外，还提出基于 KV 缓存本身的评分（如 Lag-KV），使用滞后归一化（因果形式）消除域级幅度偏移，适合无需输出隐藏状态的部署。
- **算法流程**（文字说明）：
  - 在解码步骤 t，进行一次标准前向传播（设置 `output_hidden_states=True` 但不设置 `output_attentions=True`），获取各层隐藏状态和 KV 缓存。
  - 对每层计算 L2 差分，取 Band A 和 Band B 的滚动均值/标准差，得到 z-score。
  - 计算最终评分 `z_10 - z_21`。
  - 保留 prompt token、近期窗口（min(128, K/4)），对剩余 token 按评分排序，丢弃最低评分者，使缓存大小不超过预算 K。
- **FA2 兼容性**：评分仅使用隐状态和已缓存 KV 向量，无需物化注意力矩阵，因此可直接在 FlashAttention 推理栈中运行，无额外内存占用。

## 6. 主要结论与发现

- **准确率**：
  - MATH-500 上，4096 缓存下 EpiKV 达 72%，与最强注意力基线 ThinKV (71%) 持平，高于 H2O (67%)；紧预算（≤1024）下 FA2 方法不及混合方法（Segment-HS 36%）。
  - AIME-2024 上，8192 缓存下 Lag-KV 达 37%，优于所有注意力基线（ThinKV 30%, H2O 33%）；EpiKV 达 33%。
- **速度**：在 AIME-2024 8192 缓存下，Lag-KV 每问题 440.5 秒，比最快注意力基线 ThinKV (721 s) 快 1.6×，比最慢 RaaS (1239 s) 快 2.8×。
- **内存**：FA2 方法在预存阶段无需物化注意力矩阵，可行上下文长度从 8192 扩展到 65536（16 倍）。在解码阶段，峰值内存主要由缓存预算决定，所有方法在紧预算下节省约 2.9 GB。
- **层解剖发现**：Band A（7–13）正相关、Band B（18–25）负相关的规律在竞赛数学数据上一致，但在简单算术（GSM8K）上偏移到更早层，表明重要性信号的位置随任务难度变化。
- **位置趋势**：原始隐藏状态差分携带单调位置趋势，因果滚动 z-score 可有效消除，提升排名质量。

## 7. 优点

- **无需注意力矩阵**：评分完全基于隐藏状态或 KV 向量，兼容 FlashAttention，避免 O(n²) 内存，可支持极长上下文。
- **即插即用**：无需训练、分类器或定制内核，可直接整合到 vLLM、TGI、SGLang 等生产推理栈。
- **因果在线评分**：每个 token 在生成后立即确定生死，无延迟窗口（对比 ThinKV 的 τ=128 刷新窗口）。
- **速度与准确率双优**：在关键部署预算（4096–8192）下，匹配甚至超越最强的注意力基线，同时快 1.6–2.8 倍。
- **可解释性**：通过层解剖揭示了两波段重要性分布，并提供反事实重要性标签作为验证资源。

## 8. 不足与局限

- **样本量限制**：AIME-2024 仅 30 个问题，有效样本小，置信区间宽；结论需合并更多年份稳固。
- **模型与规模单一**：仅测试 DeepSeek-R1-Distill-LLaMA-8B，未验证其他架构（如 Llama、Mistral）或更大/更小模型。
- **批量与多 GPU 未实测**：吞吐量仅从 KV 缓存算术推算（图6），而非端到端测量；多 GPU FlashAttention 遇到内核协调故障，因此所有 flash 基准使用单 GPU。
- **紧预算性能下降**：在 ≤1024 token 的极紧预算下，FA2 方法仍弱于使用了注意力+隐藏状态的混合方法（Segment-HS），该混合方法牺牲了 FA2 兼容性。
- **任务难度依赖**：层索引（第 10 和 21 层）是针对竞赛数学选择的，在其他难度任务上需调整，属于超参数。
